# sqlite_plus browser

A database browser on the sqlite_plus engine. It opens a file, shows the schema, pages through rows, edits a cell, and runs one SQL statement. The structure tree has three columns: Name, Type, and Schema. Tables, indices, views, and triggers are folders. A table expands to its columns, and each column's schema text includes the type, primary key, NOT NULL, default, and foreign key. Each column header opens a menu for A to Z, Z to A, and a search of the whole table. The pager has first, previous, next, last, and go to. The SQL editor is a JetBrains Mono code view. It colors the statement and formats it while it is typed: a newline indents inside parentheses, a comma inside parentheses starts a new line, and a finished statement puts each column or clause on its own line. The completion popup lists only the next valid token, sits beside the caret, and closes when the tap is outside it. A column suggestion shows its declared type, such as INTEGER or TEXT, beside the name. The page keeps a short log of statements that ran. A read that has no outer `LIMIT` is shown 50 rows at a time, and the next page reads the following rows. A statement that already has `LIMIT` keeps that bound and still pages the grid. A wide window keeps the schema beside the rows. A narrow window puts the schema in a drawer and Rows, SQL, and Graph in a bar. On that narrow SQL page the statement fills one screen and the result fills the next. Create table and Create index open a form for the name, columns, primary key, and indexed columns, and they apply that statement without opening the SQL editor. Add column does the same for a table that already exists: name, type, NOT NULL, default, and an optional reference. Those three actions are plus buttons beside their targets: Create table beside Tables, Add column beside each table, and Create index beside Indices. The new-table form lists each column on its own card, with the name, the type, the key, and NOT NULL together. Graph pans across the whole board, zooms with a pinch or the plus and minus buttons, and a table can be dragged to another place. The board does not show an instruction paragraph. Tapping a column marks it as the child. Every column that cannot be the parent key is disabled, and each key column on another table is highlighted. Tapping a highlighted column asks for confirmation before anything is written. Confirming attaches the foreign key to the selected column. A column that already has a foreign key has no available parent. The menu item Close database returns to the home screen. A database with unsaved changes asks before it closes. Dart classes gives each ordinary table its own card, with the class name, the SQL table, and the source in its own color. How to use opens four numbered steps: save the file under `lib/`, add the packages, run `dart run sqlite_plus_generator` from the package root, and open `sqlite_plus_migrations.g.dart`. An index page shows how many entries it stores and how many pages it uses. The count includes a key that was promoted onto an interior page. The launcher name is SQLite Browser, and the open file stays under that title. The launcher mark is a cream field, an emerald database cylinder, and a feather. A result, a saved change, and an error each appear as a colored card: blue for a row count, emerald for a change, and red for a failure such as a unique constraint. A running statement paints its card above the schema drawer. With no database open, the first screen offers Open and the recent files. A recent path is read again from that path; a phone file that has no durable path is kept as a copy in the app. Android registers the app for sqlite mime types and for the extensions `.db`, `.sqlite`, `.sqlite3`, and `.db3`.

The engine is pure Dart. This program does not use FFI, native SQLite, or WASM.

```sh
cd browser
flutter run -d linux
flutter run -d windows
flutter run -d macos
flutter run -d android
flutter run -d ios
```

New starts an empty memory image. Open reads the file bytes and passes them to `MutableSqliteDatabase.fromImage`. Save writes `exportImage()` through the platform save dialog. A write marks the title unsaved until that save finishes.

The image has to be a complete rollback database. A WAL file is rejected by the engine with `Writer requires a complete rollback-format database image`. One statement runs at a time. A table with `WITHOUT ROWID` can be read here; cell edits use `rowid`, so that table is changed from the SQL page. Blob cells show their length and stay unchanged by the cell editor. The cell editor follows the declared type: an integer has a stepper, a real has a decimal field, text is a multiline field, a boolean is on or off, and a date or time can be picked. A `NOT NULL` column has no NULL switch.

Add sample rows creates `books` and inserts Kept Garden (320 pages) and Other Atlas (40 pages).

On Linux x64, Flutter 3.47.9 and Dart 3.13.7, `flutter analyze --fatal-infos` reported no issues and `flutter test` passed 38 tests: seventeen session tests, one completion test, one model export test, and nineteen widget tests. The SQL editor is a JetBrains Mono code view. Its font does not inherit the theme letter spacing, so the caret and the selection sit on the same glyphs as the highlight. In `CREATE INDEX idx_name ON events (` the caret at `events` lines up with that word. A statement paints a Running card, with the statement text and an indeterminate progress bar, before the work starts. Add column opens a form for an existing table: name, type, NOT NULL, a default for the rows already stored, and an optional reference. `note` on `events` is stored as `"note" TEXT NOT NULL` with default `Kept`. Typing `SEL` opens the popup beside the caret, a tap outside closes it, and choosing the row inserts `SELECT`. A finished `CREATE TABLE` keeps `PRIMARY KEY` on one line. The sample grid shows Kept Garden at 320 pages. The structure tree shows `Tables (1)`, `Indices (0)`, `id` as PK, `title` as TEXT, and the column text `"title" TEXT NOT NULL`. The pages cell opens as an integer editor, the stepper changes 320 to 321, and save stores 321. After `SELECT title` the popup offers `FROM` and `AS`. A full page of 50 rows leaves the exact count for `countRows`, and the next page is the remaining rows. A 400-wide window runs `SELECT n FROM tiny` on the query screen and shows the grid only after switching to the result. The new-table form creates `notes` with its primary key, and the new-index form creates `idx_notes_title`, both without opening the SQL editor. That empty index shows 0 entries and a size in KB. An index over 300 rows reports 300 entries, and the same table's partial index `value > 0` reports 299. On the graph, dragging `books` moves its card, and panning the empty board moves every card. After `books.title` is chosen, `authors.name` and `books.id` do not accept a tap, and `authors.id` is the highlighted key. Confirming shows `→ authors.id` on `title`. Choosing `title` again, after it has a foreign key, leaves `authors.id` disabled. Close database on a dirty image stays open when Stay is chosen, and returns to the home screen when Continue is chosen. Creating an index while the schema drawer is open still hit-tests the Running card. Sorting `pages` A to Z puts Other Atlas above Kept Garden, and searching `title` for Kept hides Other Atlas. Zooming in makes the graph board wider, and zooming out brings it back. Deleting a row asks first, and Cancel leaves the row in place. `DELETE FROM books` asks before it runs, and confirming removes the remaining row. After `SELECT ` the suggestion for `title` shows TEXT and the suggestion for `id` shows INTEGER. Dart classes for `books` shows the Books card. How to use is closed until it is opened, and then it shows `dart run sqlite_plus_generator`. Copy reports Copied. An `authors` table with a unique `name`, a `books.author_id` cascade reference, a blob, a composite key, a virtual table, and a view exports the ordinary tables and leaves the virtual table, its internal tables, and the view in comments. A fresh session shows SQLite Browser, Open, and a remembered `sample.db`, and opening that row shows `events` and `kept`. `flutter build linux` was not run on that machine because `gtk+-3.0` and Ninja were not installed.
