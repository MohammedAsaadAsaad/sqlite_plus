# sqlite_plus browser

A database browser on the sqlite_plus engine. It opens a file, shows the schema, pages through rows, edits a cell, and runs one SQL statement. The structure tree is one column. Tables, indices, views, and triggers are folders. A table expands to its columns. Each column has a symbol for its type, the declared text length when the type has one, and PK when it is a key. A foreign key is the next line, `→ table.column`. An index shows its columns beside its name. Those links used to sit above the rows, and the rows page no longer shows them. The create statement stays on the open table. Each column header opens a menu for A to Z, Z to A, and a search of the whole table. The pager has first, previous, next, last, and go to. The SQL editor is a JetBrains Mono code view. It colors the statement and formats it while it is typed: a newline indents inside parentheses, a comma inside parentheses starts a new line, and a finished statement puts each column or clause on its own line. The completion popup lists only the next valid token, sits beside the caret, and closes when the tap is outside it. A column suggestion shows its declared type, such as INTEGER or TEXT, beside the name. Ran statements are listed on the Log tab, not under the editor. The list keeps the latest 12 statements from the open session. A read that has no outer `LIMIT` is shown 50 rows at a time, and the next page reads the following rows. A statement that already has `LIMIT` keeps that bound and still pages the grid. A wide window keeps the schema beside the work. The rail starts at half the window, and its divider can be dragged. A narrow window puts the schema in a drawer and Rows, SQL, Graph, and Log in a bar. Opening that drawer again scrolls to the selected object. On that narrow SQL page the statement fills one screen and the result fills the next. Create table and Create index open a form for the name, columns, primary key, and indexed columns, and they apply that statement without opening the SQL editor. Add column does the same for a table that already exists. The form groups the column, its rules, and an optional reference, and Cancel and Add stay in view. Text can take a length, stored as `VARCHAR(n)`. An integer can take a digit count, `INTEGER(n)`. Real and numeric can take digits and decimal places, such as `REAL(10, 2)`. A column that references another table has a button in its header. That button loads the matching rows from the other table, using the values on this page, and shows one table directly under the column. If the column references more than one column, the form asks which one to use. Those three actions are plus buttons beside their targets: Create table beside Tables, Add column beside each table, and Create index beside Indices. The new-table form lists each column on its own card, with the name, the type, the key, and NOT NULL together. Graph pans across the whole board, zooms with a pinch or the plus and minus buttons, and a table can be dragged to another place. The arrangement is stored in `graphs.json` in the app data folder, under the database path. Opening that file again restores the cards. A table that another program removed is dropped, and a new table is placed beside the ones that remain. A memory database has no path, so its arrangement is not stored. The layout is not written into the database file. The board does not show an instruction paragraph. Tapping a column marks it as the child. Every column that cannot be the parent key is disabled, and each key column on another table is highlighted. Tapping a highlighted column asks for confirmation before anything is written. Confirming attaches the foreign key to the selected column. A column that already has a foreign key has no available parent. The menu item Close database returns to the home screen. A database with unsaved changes asks before it closes. Dart classes gives each ordinary table its own card, with the class name, the SQL table, and the source in its own color. How to use opens four numbered steps: save the file under `lib/`, add the packages, run `dart run sqlite_plus_generator` from the package root, and open `sqlite_plus_migrations.g.dart`. An index page shows how many entries it stores and how many pages it uses. The count includes a key that was promoted onto an interior page. The launcher name is SQLite Browser, and the open file stays under that title. New, Open, and Save are in the more menu, each with its icon. The launcher mark is a cream field, an emerald database cylinder, and a feather. A result, a saved change, and an error each appear as a colored card: blue for a row count, emerald for a change, and red for a failure such as a unique constraint. A running statement paints its card above the schema drawer. With no database open, the first screen offers Open, Learn SQL, and the recent files. Learn SQL is also in the more menu. It has twelve levels, from reading rows to a report that joins, groups, and labels a count. A level shows examples with the result of running them, then three questions, then one statement at a time. A wrong answer stays on that question. A statement that does not match stays on that step. The next level opens when the level is passed. The practice field uses the same editor as the SQL page: it colors and formats the statement while it is typed, and it suggests the next token from the tables in that step. The course runs on sqlite_plus and does not cover every SQLite feature. A recent path is read again from that path; a phone file that has no durable path is kept as a copy in the app. Android registers the app for sqlite mime types and for the extensions `.db`, `.sqlite`, `.sqlite3`, and `.db3`.

The engine is pure Dart. This program does not use FFI, native SQLite, or WASM.

```sh
cd browser
flutter run -d linux
flutter run -d windows
flutter run -d macos
flutter run -d android
flutter run -d ios
```

New starts an empty memory image. Open reads the file bytes and passes them to `MutableSqliteDatabase.fromImage`. Save writes `exportImage()` through the platform save dialog. A write marks the title unsaved until that save finishes.

The image has to be a complete rollback database. A WAL file is rejected by the engine with `Writer requires a complete rollback-format database image`. One statement runs at a time. A table with `WITHOUT ROWID` can be read here; cell edits use `rowid`, so that table is changed from the SQL page. Blob cells show their length and stay unchanged by the cell editor. The cell editor follows the declared type: an integer has a stepper, a real has a decimal field, text is a multiline field, a boolean is on or off, and a date or time can be picked. A `NOT NULL` column has no NULL switch.

Add sample rows creates `books` and inserts Kept Garden (320 pages) and Other Atlas (40 pages).

On Linux x64, Flutter 3.47.9 and Dart 3.13.7, `flutter analyze --fatal-infos` reported no issues and `flutter test` passed 54 tests: eighteen session tests, one completion test, one model export test, five course tests, two graph-layout tests, and twenty-seven widget tests. The SQL editor is a JetBrains Mono code view. Its font does not inherit the theme letter spacing, so the caret and the selection sit on the same glyphs as the highlight. In `CREATE INDEX idx_name ON events (` the caret at `events` lines up with that word. A statement paints a Running card, with the statement text and an indeterminate progress bar, before the work starts. Add column opens a form for an existing table: name, type, NOT NULL, a default for the rows already stored, and an optional reference. `note` on `events` is stored as `"note" TEXT NOT NULL` with default `Kept`. A text length of 160 is previewed as `VARCHAR(160)`, and `amount` is stored as `REAL(10, 2)`. Opening the related rows of `books.author_id` shows Ada and not Grace. Opening `title` replaces that table. A column that references two columns asks which one to use, and loading `people.id` shows Person. Typing `SEL` opens the popup beside the caret, a tap outside closes it, and choosing the row inserts `SELECT`. A finished `CREATE TABLE` keeps `PRIMARY KEY` on one line. The sample grid shows Kept Garden at 320 pages. The structure tree shows `Tables (1)`, `Indices (0)`, and `id` as PK. `title` is a text symbol, and the side list does not show the schema text. The pages cell opens as an integer editor, the stepper changes 320 to 321, and save stores 321. After `SELECT title` the popup offers `FROM` and `AS`. A full page of 50 rows leaves the exact count for `countRows`, and the next page is the remaining rows. A 400-wide window runs `SELECT n FROM tiny` on the query screen and shows the grid only after switching to the result. The new-table form creates `notes` with its primary key, and the new-index form creates `idx_notes_title`, both without opening the SQL editor. That empty index shows 0 entries and a size in KB. An index over 300 rows reports 300 entries, and the same table's partial index `value > 0` reports 299. On the graph, dragging `books` moves its card, and panning the empty board moves every card. After `books.title` is chosen, `authors.name` and `books.id` do not accept a tap, and `authors.id` is the highlighted key. Confirming shows `→ authors.id` on `title`. The schema list shows the same `→ authors.id`, and the rows page does not show `title → authors.id`. Choosing `title` again, after it has a foreign key, leaves `authors.id` disabled. Close database on a dirty image stays open when Stay is chosen, and returns to the home screen when Continue is chosen. Creating an index while the schema drawer is open still hit-tests the Running card. Sorting `pages` A to Z puts Other Atlas above Kept Garden, and searching `title` for Kept hides Other Atlas. Zooming in makes the graph board wider, and zooming out brings it back. Deleting a row asks first, and Cancel leaves the row in place. `DELETE FROM books` asks before it runs, and confirming removes the remaining row. After `SELECT ` the suggestion for `title` shows TEXT and the suggestion for `id` shows INTEGER. Dart classes for `books` shows the Books card. How to use is closed until it is opened, and then it shows `dart run sqlite_plus_generator`. Copy reports Copied. An `authors` table with a unique `name`, a `books.author_id` cascade reference, a blob, a composite key, a virtual table, and a view exports the ordinary tables and leaves the virtual table, its internal tables, and the view in comments. Reopening the schema drawer puts the selected table in view: `t9` is on screen and `t0` is above it. On a 420-wide window the title `SQLite Browser` is fully visible, and the more menu lists New, Open, and Save. A fresh session shows SQLite Browser, Open, and a remembered `sample.db`, and opening that row shows `events` and `kept`. Learn SQL opens from the home screen. A wrong answer on the first question stays there until Retry. `SELECT ` suggests `title` with type TEXT. `SELECT 1` reports `The result does not match.` The official statement reports Passed. Finishing the level opens Filtering rows, and the level after that stays locked. On a 1400-wide window the schema rail is 700 wide, and dragging the divider makes it narrower. After `SELECT 1` the SQL page does not show the log, and the Log tab lists that statement. A saved graph keeps a dragged `books` card for the same path, drops `books` when that table is gone, and places `notes`. `flutter build linux` was not run on that machine because `gtk+-3.0` and Ninja were not installed.
