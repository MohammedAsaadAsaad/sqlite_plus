## Query and format limits

General SQLite conformance is not claimed. See README for the current grammar.
Unsupported SQL should fail explicitly. A mutable query reads its image through a shared read-only view and does not copy the database bytes before scanning. Query results are materialized and integer
values use BigInt to retain signed-64-bit precision. Malformed UTF text is
rejected rather than emulating native SQLite's permissive decoding. The default
record bound is 16 MiB. The parser limits SQL to 1 MiB and expression nesting to
128. Floating rendering/numeric coercion beyond the pinned cases is unverified.
Multiple MIN/MAX bare-column ambiguity and unspecified row ordering are not
portable guarantees. Window execution is materialized and is not a performance
claim. Index plans use safe equality prefixes/ranges and a constraint-count heuristic;
valid STAT1 prefix cardinalities now rank eligible indexes. Two or three comma
joins with ORDER BY and stat1 counts can be reordered. A covering read skips
the table only for columns stored in the index or a rowid alias. A complete
native cost model and STAT4 sample planning remain
unsupported. `EXPLAIN SELECT 1`, constant arithmetic, a constant `WHERE`, one ordinary table scan, and one constant `INSERT` match the pinned opcode rows. A constant subquery, an integer-primary-key scan, `WITHOUT ROWID`, a virtual generated column, a typed `INSERT`, and a multi-row `VALUES` insert match the pinned opcode rows. An integer-primary-key insert and a join of two subqueries still throw. This is not a VDBE. The gap case `explain-query-plan` matches `2,0,33,'SEARCH t USING INTEGER PRIMARY KEY (rowid=?)'`. A full scan of that table is `2,0,216,'SCAN t'`. `WHERE a>1` is `2,0,196,'SEARCH t USING INTEGER PRIMARY KEY (rowid>?)'`. `EXPLAIN QUERY PLAN SELECT 1` is `1,0,0,'SCAN CONSTANT ROW'`. `EXPLAIN QUERY PLAN SELECT * FROM missing` is `no such table: missing`. Costs and addresses that were not compared are not claimed. Multi-table addresses and stat1-adjusted costs were not compared.

Byte-image reads and `ReadOnlyFileStorageBackend` do not lock or recover a sidecar. `openReadOnlyFile` holds a shared lock on database byte 0x40000002 until close, recovers a hot `-journal` or a pending `-wal` in memory, and does not modify those files. If `-shm` exists it takes one shared lock among bytes 123–127 and does not create that file. A checkpointed or recovered write version 2 image opens. Mismatched read and write versions are rejected. `browse` reads a single-table `LIMIT`/`OFFSET` window, including a bound limit and ascending `rowid` order, and stops after that window. `query` still loads its input: `SELECT` and `SELECT ... LIMIT 100000` on an 80-row table read the same number of pages, and `browse` of `LIMIT 1` reads fewer. `LIMIT 0` adds no page reads. The window, an empty offset, and a join that still uses `query` match the pinned CLI. A stored `zeroblob(16777217)` makes `query` throw `FormatException`; `browse` returns that blob, and the pinned CLI reports length 16777217 with zero endpoints. A well-formed record larger than 1000000000 bytes was not created, so the CLI length-limit text was not compared. No wall-clock timing was run. A traversal/seek may yield rows before discovering later corruption;
unvisited seek branches are not validated. Raw BtreeRecord values are physical
records: rowid INTEGER PRIMARY KEY fields are NULL and the rowId is separate.
WITHOUT ROWID uses physical primary-key-first column order. Raw traversal provides no cross-tree/freelist integrity guarantee; the bounded
PRAGMA checks below use the validated image path. Media repair is not claimed.

## Writes and durability

The image writer checks B-tree/overflow ownership and freelist coverage before
reconstruction. A single changed rowid table can reuse its pages and the
freelist. Same-length overflow updates patch the overflow bytes. Other shapes,
including a key change to an expression or partial index, still use a compact
rebuild. Compact rebuilds maintain supported indexes and schema roots.
Complete images are required, with a 64 MiB bound. A reserve of 0 keeps the
previous page geometry. A nonzero reserve rebuilds when auto-vacuum is off.
Auto-vacuum together with a reserve is rejected. Fast page patches still
require a zero reserve.
Auto-vacuum images are rebuilt with pointer maps. NONE images keep the freelist
fast path. Image mutation favors a simple atomic boundary over in-place
splits; write scaling and all native schema edge cases remain open. Unsupported schema syntax or constraints may reject access; expression/partial
indexes support the documented deterministic grammar and predicate proofs.
ALTER supports ADD/RENAME/DROP COLUMN and table renaming. Resolved view and trigger references are rewritten.
